# このリポジトリでの適用

GitHub Pages/Viteでは `node scripts/viewer/install-public.mjs ROUTE_CODE` を使い、`public/d/ROUTE_CODE/` の閲覧部分だけを生成する。`npm run build` のprebuildも選択された既存ルートに同じ処理と暗号化公開検査を実行する。本文・パスワード・他社ルートを移行しない。

共通コード・受入条件の原典は顧客デモSitesソースの `scripts/viewer/`（導入元commit `10dfeeb1e366ee82da570f7cdb312f5729839cca`）とVaultの「デモ制作・閲覧操作_共通仕様」。`gate.js` と `service-guide-navigation.js` はそのまま再利用し、ホスト固有処理はinstall-public.mjsへ分離した。原典更新時は差分・ハッシュ・PC/スマホ操作を照合する。

# 暗号化デモの閲覧・画面遷移 正典

今後の顧客デモはこの実装と受入条件を使う。対象は静的HTMLをパスワードで復号し、sandbox付きiframe/srcdocで表示するデモ。顧客別の文章・画像・会話の正本はVaultの案件に置く。秘密値や顧客HTMLをこのリポジトリへ保存しない。

## 共通実装

- `gate.js`: 外側の閲覧、暗号の復号、タブ内の30分保持、履歴、終了。
- `service-guide-navigation.js`: ページ内リンクを安全にスクロールし、4サービスガイドの画面状態を通知・復元するアダプター。
- `build.mjs`: 上記からルート専用のindex.html/gate.js/gate.cssを生成する。公開用gate.jsを直接編集しない。
- `test_viewer.py`: 実際の暗号化資料でPC・スマートフォン相当の回帰確認を行う。

既存ルートの閲覧部分だけを更新する場合：

```sh
node scripts/viewer/build.mjs ROUTE_CODE
python3 scripts/viewer/test_viewer.py --case /absolute/case/publication-record.json --report /absolute/case/viewer-validation.json
```

case JSONには `code` と `password_file` を指定する。公開検証には `--url https://approved-host/d/ROUTE_CODE/` を追加する。プラットフォームの接続トークンが必要な場合は `--headers-stdin` でセッションメモリから渡し、ファイル・argv・ログに残さない。

`encrypt-demo.mjs` と `customer-demo/package.mjs` は新規パッケージ作成時に共通ビューアーを組み込む。他の暗号化生成経路を使う場合も、最後にbuild.mjsを実行し、既存の閲覧コードへ戻さない。既存の他社ルートへの一括反映は行わず、対象・承認・互換性を確認する。

## 必須の挙動

1. ロゴ、本文ジャンプ、セクションリンクはiframe内の同じHTMLを移動する。未処理の `href="#..."` によって外側の専用URLをiframeへ読み込ませない。リンク先がなくても再読み込みしない。
2. 一覧・サービス説明・操作体験・活用案内は外側のブラウザ履歴へ登録し、戻る／進むで復元する。画面内の戻るでパスワード入力へ戻さない。回答変更は現在の履歴を更新し、回答の一つずつをブラウザ履歴へ積まない。
3. 同一タブの再読み込み・ページ再訪では、解除から最大30分、復号鍵と選択状態をsessionStorageから復元する。期限を操作ごとに延長しない。
4. パスワード・復号したHTML・画像をlocalStorageやsessionStorageへ保存しない。保存する復号鍵は同じ資料を開ける機密情報であり、通常の会員認証やサーバー側の失効ではない。sessionStorageはタブ単位だが、ブラウザのタブ複製・セッション復元の挙動はブラウザに依存する。30分期限はブラウザ内の制御であり、取得済みデータの強制失効ではない。
5. 「デモを閉じる」と期限到達で保存鍵・状態を削除し、iframeを空にする。閉じた後の戻る・進む・再読み込みで再解除しない。
6. 資料のcode/salt/IVに鍵を結び付け、再暗号化された資料や別顧客へ流用しない。保存不可・復元失敗時はパスワード入力へ戻し、手動閲覧を妨げない。
7. sandboxのsame-origin権限を追加しない。postMessageは送信元window・チャネル・状態形式を照合する。応募・予約・メール・通知など外部処理を操作検証で実行しない。

## ガイド以外のデモ

ページ内リンク修正と30分の閲覧保持は共通。画面履歴・回答復元はHTMLごとの状態構造に対応するアダプターが必要。別アプリへ4サービスの変数名をそのまま適用して完成扱いしない。操作上の成功と暗号化・配備成功は別に確認する。

## 公開前の受入条件

- 実際の暗号化された入口から誤パスワード拒否・正しい解除を確認する。
- PCとスマートフォン相当で、全サービスの画面内戻る、ブラウザ戻る／進む、回答途中の再読み込み、ロゴ・本文・セクションリンクを確認する。
- 回答保持、閉じた後の再入力、期限切れ、資料の差替え、別タブ、他社ルートへの影響なしを確認する。
- sandbox内に入口が表示されないこと、JavaScript例外なし、パスワードと回答を送信しないことを確認する。
- 暗号化本文・画像と他社の配信ファイルが対象外ならハッシュ不変を確認する。
- 最終ソース版を固定して検証し、同じ版を保存・配備する。公開版でも復号後の操作を確認し、到達できない場合はローカル検証と公開確認を区別する。

公開先固有の計測通信は、送信先・メソッドのメタデータを案件へ記録する。全POSTを応募送信と決めつけず、デモの資産取得と回答・秘密値の非送信を別に検証する。`test_viewer.py --smoke` は公開後の主要動作確認用であり、4サービスと期限等の完全なローカル受入を代替しない。
